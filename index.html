Low-Latency Sharded Game Server

2024 – 2026
  • C++23
  • Lock-free
  • kqueue / epoll
  • io_uring
  • NUMA

A real-time multiplayer server built to a single rule: no mutex on any steady-state path. An acceptor feeds N I/O threads, which feed M simulation shards, joined only by bounded single-producer/single-consumer rings. Each shard owns its entities exclusively, so the tick body has nothing to lock.

Messages are fixed-layout PODs cast in place from the socket buffer — no parse step, no allocation — with alignment enforced as a protocol invariant and a consteval check that turns an unhandled message type into a build error rather than a production log line.

10,937lines of C++23, zero deps
2.25 µsmedian service time
78.7K/sat p50 380 µs, 2.3 cores
70 / 304Ktests / assertions, ASan+UBSan

Zero steady-state heap allocations, verified by interposing global operator new. Load is generated open-loop against a fixed schedule and timed from when each request was due, so the harness is coordinated-omission-free — and every run prints its own reasons to be distrusted.

CacheFlow — 3D-Parallel KV Cache Restoration

Published · arXiv:2604.25080
  • Python
  • vLLM
  • LMCache
  • Multi-GPU
  • Research

Research contribution under Prof. Fan Lai at UIUC. CacheFlow parallelizes KV-cache restoration across tokens, layers and GPUs, cutting time-to-first-token by 10–62% across Qwen3-8B, Llama-3.1-8B and Qwen3-30B-A3B.

I prototyped the bidirectional two-pointer restoration strategy at token-chunk and layer granularity: paired worker threads converge from opposite ends of a range, one recomputing KV on the GPU and the other loading from cache storage. Because those two paths contend for entirely different resources — SM time versus storage bandwidth — running them toward each other keeps both saturated instead of serializing, and the meeting point self-adjusts to whichever side is faster on that hardware.

Chess Engine with Alpha-Beta Search

2024 – 2026
  • C++17
  • Qt5
  • CMake
  • Search

Negamax alpha-beta with iterative deepening, quiescence search, a 64 MB transposition table, MVV-LVA ordering with killer moves and a history heuristic, null-move pruning with the canonical zugzwang guards, and late move reduction. Fully deterministic — no sampling, no MCTS, no neural evaluation in the move path.

Correctness is gated on perft: the engine enumerates the full legal game tree and matches published node counts exactly through depth 6 (119,060,324 positions). Every optimization was accepted only if that count stayed exact — which is what made replacing the board representation safe.

~1840 Elo95% CI 1730–1932
1.37Mnodes / sec
49×perft(5): 8.55s → 176ms
790×fewer heap allocations

The board is a 192-byte POD — exactly three cache lines — stored by value instead of 64 heap-allocated pieces, with per-ply preallocated move buffers so the search allocates nothing in the hot path.

Bharat Bazar — Conversational Commerce

2026
  • FastAPI
  • LangChain
  • Firestore
  • React / TS
  • Terraform
  • GCP

An end-to-end agentic storefront on GCP: a FastAPI/WebSocket backend, a 15-tool LangChain agent layer, and a React/TypeScript client supporting natural-language product discovery through checkout.

The interesting half is correctness under failure. Payment fulfillment is idempotent, built on Firestore transactional claims so exactly one caller can fulfil an order — duplicate webhooks are refused, crashed in-progress claims are reclaimed after a staleness window, and stock is reconciled after payment. Completion events are safe to arrive in any order, or more than once.
